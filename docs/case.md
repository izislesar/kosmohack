## 0. Краткое содержание задачи

Разработать комплекс из двух модулей, работающих по спутниковым снимкам:

1. Первый по инфракрасным каналам находит пиксели активного горения и отделяет их от техногенных термоаномалий — газовых факелов, промышленных площадок и т.д.
2. Второй по паре мультиспектральных снимков «до» и «после» выделяет контур гари и относит каждый её пиксель к слабой, средней или сильной степени поражения растительного покрова.
3. Дополнительно команда разрабатывает информационно-аналитический сервис, который по пространственно-временному запросу возвращает карту термоточек, векторные контуры пройденной огнём площади и расчёт площади по степеням поражения.

Схема решения (рис. 1 в PDF): два модуля → общий файл ответа → сервис поверх обоих.

## 1. Проблематика

Значительная часть территории страны — высокая природная горимость с апреля по октябрь. Типы пожаров:

- степные и ландшафтные по сухой траве: скорость километры в час, живут часы;
- палы стерни: многочисленны и кратковременны;
- пожары в пойменных лесах и насаждениях на песках: устойчивая гарь с повреждением древостоя.

Оперативность локализации прямо влияет на ущерб.

### 1.1. Ограничения глобальных продуктов термоточек (NASA FIRMS на MODIS и VIIRS)

Выдаются автоматически, но критичны именно для такой территории:

- высокая доля ложных срабатываний на техногенных источниках — факелах, металлургии, объектах теплоэнергетики; в промышленно освоенных районах их доля может превышать долю настоящих пожаров;
- ложные срабатывания на отражающих поверхностях: металлические кровли, теплицы, водная поверхность при солнечном блике;
- пропуск пожаров малой площади и низкой интенсивности, пропуски из-за облачности, дыма и несовпадения времени пролёта с временем горения.

### 1.2. Вторая задача — оценка гари после ликвидации

Сейчас решается наземным обследованием: выборочно, с задержкой в недели, без единой методики. Распределение площади по степеням определяет мероприятия:

- слабое поражение — естественное восстановление;
- сильное — искусственное лесовосстановление, входит в расчёт ущерба.

### 1.3. Региональная специфика, осложняющая задачу

- гарь на травянистых сообществах зарастает за 2–4 недели, лесная держится месяцами;
- высокая доля пашни даёт массу ложных контуров: убранное / сожжённое по стерне / свежевспаханное поле спектрально похоже на гарь;
- в период активного горения территория закрыта дымом.

## 2. Что разрабатывает команда (комплект из 5 элементов)

1. **Модуль детекции активного горения.** Вход — AF-чип на сетке 375 м: каналы VIIRS I1–I5 и вспомогательные слои. Выход — бинарная маска: 1 = пиксель природного горения, 0 = всё остальное, включая техногенные термоаномалии.
2. **Модуль картирования и классификации гарей.** Вход — BS-чип на сетке 20 м: пара снимков Sentinel-2 «до» и «после», пара радиолокационных снимков Sentinel-1, рельеф и тип покрова. Выход — маска со значениями 0–3 (0 фон, 1/2/3 степени).
3. **Файл submission.csv.** Обе маски кодируются в едином файле в формате RLE.
4. **Информационно-аналитический сервис.** Веб-приложение или API: по полигону и интервалу дат — карта термоточек, векторные контуры гарей, аналитическая справка с площадью и распределением по степеням.
5. **Репозиторий, отчёт и презентация.**

## 3. Продуктовая цель (прототип аналитического слоя регионального контура)

- **Оперативный контур** — очищенный от техногенных срабатываний поток термоточек снижает число ложных выездов дежурных сил.
- **Послепожарный контур** — векторные контуры гарей с распределением по степеням передаются в региональную ГИС, используются при планировании лесовосстановления и расчёте ущерба.
- **Отчётный контур** — воспроизводимая методика расчёта площадей заменяет выборочное наземное обследование.
- **Требование к интеграции** — программный интерфейс, позволяющий запрашивать результат по территории и периоду без ручных операций с растрами.

## 4. Теоретический раздел (предметный минимум, без рекомендаций по архитектуре)

### 4.1. Глоссарий

| Термин | Значение в рамках соревнования |
|---|---|
| Термоточка | Пиксель с аномально высоким излучением в среднем ИК, интерпретируемое как открытое горение в момент пролёта |
| Гарь | Территория, пройденная огнём: устойчивое изменение спектральных характеристик растительного покрова по паре до/после |
| Степень поражения | Категория повреждения растительности внутри гари: слабая / средняя / сильная |
| Чип | Прямоугольный фрагмент сцены фиксированного размера — единица выдачи и оценки |
| AF-чип / BS-чип | Чип детекции активного горения (Active Fire) / картирования гарей (Burn Severity) |
| MIR / TIR | Средний (3–5 мкм) и тепловой (8–14 мкм) ИК. VIIRS I4 (3.74 мкм) и I5 (11.45 мкм) |
| NIR / SWIR | Ближний (~0.86 мкм) и коротковолновый (1.6 и 2.2 мкм) ИК. Sentinel-2 B8A, B11, B12 |
| L2A | Sentinel-2: отражение на поверхности после атмокоррекции. В кейсе именно он |
| SCL | Scene Classification Layer S2: облако, тень, вода, растительность, грунт |
| NBR | Нормализованный индекс гарей: NBR = (B8A − B12) / (B8A + B12) |
| dNBR | Разностный NBR между датами до/после. Базовый индикатор степени |
| RdNBR | Относительный dNBR: dNBR / √\|NBR(до)\|. Снижает зависимость от биомассы, только где биомасса есть |
| ЦМР (DEM) | Цифровая модель рельефа. В кейсе — Copernicus DEM GLO-30, приведённый к сетке чипа |
| SAR, VV / VH | Радар с синтезированной апертурой и поляризации. Не зависит от облачности, дыма, освещённости |
| Техногенная термоаномалия | Постоянный/регулярный антропогенный источник тепла: факел, печь, промплощадка, свалка |
| IoU | Пересечение / объединение предсказанной и эталонной масок |
| F1-мера | Гармоническое среднее точности и полноты |
| mIoU | Среднее IoU по нескольким классам |
| RLE | Запись маски парами «начальный пиксель — длина серии» |
| Public / Private test | Открытая и закрытая части теста. Первая — промежуточный лидерборд, вторая — итог |

### 4.2. Почему горение видно из космоса

Любое тело излучает энергию по температуре. Фон суши ~300 K — максимум ~10 мкм (тепловой). Очаг 600–1200 K — максимум смещается в средний ИК. Поэтому канал 3.74 мкм основной: контраст «очаг — фон» в нём на два порядка выше, чем в тепловом.

- Рис. 2: в I4 очаг ярче фона в тысячи раз, в I5 — в десятки. Разность I4 − I5 и есть признак горения.
- Субпиксельная детекция: пиксель VIIRS 14 га, но очаг в доли га поднимает среднюю яркостную температуру I4 измеримо.
- Рис. 3: очаг на 3.6% площади пикселя поднимает I4 на 237 K, I5 лишь на 52 K. I4 насыщается при 367 K — очень горячие очаги упираются в потолок.
- Стандартные алгоритмы — контекстные: кандидат если яркостная температура в MIR и разность MIR − TIR одновременно превышают статистику соседних фоновых пикселей в скользящем окне. Абсолютный порог только для очень ярких очагов.

### 4.3. Источники ложных срабатываний (фильтрация — содержательная часть модуля 1)

Три из четырёх различаются по признакам самого снимка, четвёртый — только по истории (рис. 4 — типичные значения признака):

- газовый факел по одному снимку от горения неотличим: он и правда горит. Выделяет повторяемость — детекции в одной точке из пролёта в пролёт, в том числе зимой, когда степь не горит. Эталон кейса построен на этом: карта постоянных термоточек собрана по многолетнему архиву с обязательным условием зимних срабатываний.

### 4.4. Почему гарь видна в оптике

Два противоположных эффекта: уничтожение хлорофилла/структуры резко снижает отражение в NIR; обугленный материал/зола повышает отражение в SWIR. NBR как нормализованная разность реагирует сильнее любого одиночного канала (рис. 5 — спектр до/после, B8A и B12 расходятся).

### 4.5. Почему одного порога недостаточно

Шкала dNBR USGS выведена для хвойных/широколиственных лесов. В степи/на пашне биомасса вдесятеро меньше — dNBR физически не достигает лесных значений. Один порог на чип с лесом и степью заведомо ошибочен.

- Рис. 6: пороги эталона. Лес/кустарник — шкала USGS; степь/пашня/пойма — границы по распределению dNBR внутри размеченных гарей региона.
- Следствие: степень в кейсе относительна типу покрова. «Сильная» в степи = полное выгорание травостоя, не то же что сильная в сосняке. Принято в региональных картах, позволяет сопоставить классы по объёму; при сравнении с лесными работами учитывать.
- Другие причины против одного порога:
  - фенология: урожай убран, вспашка, выгорание от засухи — положительный dNBR и ложные контуры, особенно на пашне;
  - облачность/тени: неотфильтрованное облако даёт резкое изменение индекса. SCL выдаётся, но не безошибочен, в полупустыне принимает сухую светлую почву за облако;
  - задымление: дым ослабляет видимый/NIR сильнее чем SWIR, искажая индексы;
  - быстрое зарастание: для трав отклик слабеет за недели, дата «после» влияет на площадь.

### 4.6. Радиолокация и вспомогательные слои

- Sentinel-1 C-диапазон: не зависит от облачности/дыма/времени суток. После пожара меняется обратное рассеяние: в лесу снижается объёмное рассеяние в VH из-за утраты крон, в степи меняются шероховатость/влажность (заметнее в VV). Полезна для верификации границ где оптика закрыта, но из-за спекл-шума редко даёт чистый контур сама.
- Тип покрова нужен обоим модулям: в первом отделяет застройку/пашню, во втором задаёт пороги. Рельеф объясняет вариации освещённости и влияет на скорость огня. Метео на момент пролёта выдаётся с AF-чипом.

## 6. Формат submission.csv

RLE-маски всех тестовых чипов. UTF-8, запятая, первая строка заголовок. Рис. 8 — как маска становится строкой.

| Колонка | Тип | Описание |
|---|---|---|
| chip_id | строка | из sample_submission.csv |
| class_id | целое | AF всегда 1. BS 1/2/3 — степень |
| rle | строка | пары «старт — длина» через пробел, в двойных кавычках. Пустая строка если класса нет |

Правила: нумерация построчно слева направо сверху вниз с единицы; пары по возрастанию старта; серии не пересекаются и не соприкасаются; выход за чип запрещён.

Требования:
- все строки шаблона sample_submission.csv: по 1 на AF-чип и по 3 на BS-чип, всего 447 строк без заголовка;
- набор (chip_id, class_id) полностью = шаблону; порядок произвольный;
- пропуски/NaN/пустые ячейки запрещены — отсутствие класса = пустая строка в кавычках;
- маски классов внутри чипа не пересекаются: пиксель ровно в одном классе.

Шаблон и скрипт RLE-кодирования/декодирования — в baseline.

## 7. Метрика Score (рис. 9)

Пиксели всех чипов в общий пул (микро-усреднение): суммарные TP/FP/FN, потом величины. Устойчиво к малой доле горения (0.035% в train AF).

```
precision = TP / (TP + FP)
recall = TP / (TP + FN)
F1 = 2*precision*recall / (precision+recall)
IoU(k) = TP(k) / (TP(k)+FP(k)+FN(k))
mIoU_sev = (IoU(1)+IoU(2)+IoU(3)) / 3
Score = 0.35*F1_af + 0.35*IoU_burn + 0.30*mIoU_sev
```

- Знаменатель 0 (класса нет ни в эталоне ни в преде) = 1. Класс есть в эталоне, нет в преде = 0.
- Score на private → баллы линейной нормализацией по всем прошедшим проверку: `Балл = 40*(Score_i − Score_worst)/(Score_best − Score_worst)`.
- Нет валидного submission.csv = 0 баллов по разделу метрики.

## 8. Технические требования и воспроизводимость

### 8.1. Запуск

Единый способ без правки кода:

```
python inference.py --data-dir /path/to/test --output /path/to/submission.csv
```

Принимает каталог тестовых чипов в структуре набора, обрабатывает все чипы из sample_submission.csv включая облачные, формирует файл строго по формату, exit 0 без интерактива. Скрипт обучения в репо обязателен, его запуск при проверке не обязателен.

Предпочтительно Dockerfile/готовый образ. Без Docker — однозначный README: зависимости с версиями, установка, запуск, структура каталогов, пути весов, env. Фиксация зависимостей и сидов; повторный запуск на тех же данных — дрейф метрики ≤0.005.

### 8.2. Внешние данные и модели

- ПО — только открытое и бесплатное.
- Открытые предобученные модели в публичном доступе до старта — можно при соблюдении лицензий; ссылка+лицензия в отчёте.
- Самостоятельный сбор обучающих ДЗЗ из открытых источников — можно.
- Запрещено использовать данные территорий/дат тестовой выборки. В частности запрещено применять готовые продукты горения (FIRMS, VNP14, MOD14/MYD14, Sentinel-3 World Fire Atlas) и гарей (MCD64A1, FireCCI51, GABAM, EFFIS) для ответов по тестовым чипам. Для обучения на истории — можно.
- Запрещены восстановление гео/дат тестовых чипов и ручная разметка теста.
- Нарушение = дисквалификация.

## 9. Состав итогового решения

Отсутствие обязательных элементов снижает/обнуляет баллы (см. критерии).

### 9.1. Репозиторий

Полный код: обучение, инференс, конфиги, подготовка данных, сервис. Явные точки входа, логика по модулям. README: описание + схема пайплайна, окружение/установка, структура входа, команда инференса с примером и путём submission.csv, команда обучения, получение/размещение весов, запуск сервиса.

### 9.2. Сервис (минимум)

В репо, запуск по команде из README:

- приём запроса: полигон или bbox + интервал дат;
- карта термоточек за период;
- отображение и выгрузка векторных контуров гари в GeoJSON/Shapefile;
- справка: суммарная площадь га + распределение по 3 степеням, выгрузка в машиночитаемом формате;
- REST API для того же без UI.

Можно на заранее подготовленном ограниченном наборе сцен, полный конвейер скачивания не требуется. На защите должен запускаться и отрабатывать за конечное время.

### 9.3. Отчёт (рекомендуемая структура)

Задача и протокол оценки; разбор данных «наблюдение — решение»; разбор baseline и гипотезы; подход/модель по обоим модулям; эксперименты/абляции и объяснение эффекта; инженерные/предметные решения (облачность, дисбаланс, техногенка, покров/рельеф, радар); итоговое решение и почему оно; выводы, остатки ошибок, план развития; воспроизводимость.

### 9.4. Презентация

Понимание постановки, схемы обоих модулей, итоги по компонентам метрики, демо сервиса, ограничения и развитие. 8–12 слайдов.
